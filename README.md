# 日本語学習ツール (jp-learn)

日语学习工具（终端 + Web）：以日常交流为主、阅读为辅的情景课程，保留词汇拼写、FSRS 间隔重复和听力专项练习。

支持的流程：

- 主菜单：学习新课 / 开始复习 / 查看进度 / 退出
- 主菜单：听力练习 → 听写模式 / 理解选择 → 选择已学课程 → 逐题作答

## 运行

### 终端版

```bash
cd jp-learn
npm install
npm start
```

注意：Ink 需要支持 raw mode 的交互式终端，macOS 的 Terminal / iTerm2、Windows Terminal、PowerShell 或 CMD 均可。非交互 shell 会提示无法接收方向键输入并退出。听力模式会自动探测语音引擎：macOS 用内置 `say`（Kyoko 日语声），Windows 用 PowerShell + System.Speech（日语语音包已安装时效果最佳），Linux 用 `espeak-ng` / `espeak` / `spd-say`。未检测到语音引擎时界面仍可操作，只是没有声音。

调试：设置环境变量 `JP_LEARN_SILENT=1` 可静默运行（不播放语音），便于无音频环境测试。

### Web 版

```bash
cd jp-learn
npm run web        # 开发模式，自动打开 http://localhost:5173
npm run build:web  # 构建生产包到 dist/
npm run serve:web  # 本地预览生产包 http://localhost:4173
```

Web 版支持鼠标操作；语音可选浏览器 Web Speech API 或云端合成，也可直接播放已有录音。进度通过内置接口读写 `user/progress.json`，与终端版完全一致；接口不可用时自动回退到浏览器 localStorage。

### 语音与录音版本

每个新标签页首次进入时选择供应商、模型和音色；所有页面顶部均保留「语音设置」，首次跳过后或练习途中都能随时修改，无需退出当前练习。打开设置会停止正在播放的朗读。默认配置记在 localStorage，Key 按供应商分别保留在 sessionStorage，不写入项目文件。同一标签页刷新不重复弹出设置。终端版仍使用系统语音，不受此设置影响。

| 供应商 | 模型 | 已接入音色 |
|------|------|------|
| 浏览器 | Web Speech API | 自动选择已安装的日语音色 |
| 火山引擎 | 豆包 TTS 2.0 | Hana、Bonnie、Poppy、Aoi、Lily、Ken、Minimi、Shirou |
| 阿里云百炼（北京） | Qwen3-TTS-Flash | Ono Anna、Cherry、Serena、Ethan |
| 阿里云百炼（北京） | CosyVoice-v3-Flash | Yuuna、Tomoya、Yuuma |

- 火山引擎需开通 2.0 音色及对应权限；API Key 模式默认资源 `seed-tts-2.0`。旧版 APP ID + Access Key 和显式资源 ID 配置继续兼容。
- 百炼使用北京地域 Key；CosyVoice HTTP 接口还需要北京业务空间 ID（例如 `llm-xxx`），可在设置里输入。Qwen 不填空间 ID 时使用 DashScope 北京域名。模型、音色搭配在前后端都进行校验。
- 可选服务端配置见 `.env.example`：`VOLC_TTS_API_KEY`、`DASHSCOPE_API_KEY`、`DASHSCOPE_WORKSPACE_ID`。`.env` 不提交；不要使用 `VITE_` 前缀保存凭证。
- 只在点击试听样句或练习中请求播放时合成，切换下拉选项不会自动试听。无缓存的云端合成可能计费；失败不会自动重试或切换另一供应商，浏览器语音需要主动选择。

**同一句话的多个版本**

播放入口旁的「录音版本」列出这句话已缓存的供应商、模型和音色。情景对话可先选择第几段发言，不提前显示日文答案。支持逐个试听、慢速试听，以及「本句使用」；本句选择仅保留在当前标签页会话，不修改全局配置，也不改变学习评分。「本句恢复默认配置」取消覆盖。

- 试听已有录音不需要 Key、不调用合成接口。录音文件丢失时明确报错，不自动重新合成。
- 「生成当前配置版本」需要再次确认；只生成当前选定供应商的版本。生成后需要点击「本句使用」才会覆盖本句的默认播放配置。
- 新缓存保存在 `data/audio/tts/<文本摘要>/<版本摘要>.wav|mp3`，旁边同名 JSON 保存文本、供应商、模型、音色、参数和生成时间。摘要包含文本、供应商、模型、音色、格式、采样率、语言和引擎参数；不包含 API Key。
- 旧的 `data/audio/<voice>/<sha1>.mp3` 保持原样、可继续试听和复用，界面标记为旧版缓存，不推断未知参数。新版本不会覆盖旧音频或改写旧 `index.json`。
- 慢速是本地播放速度变化，不生成额外文件。同一服务器进程对同凭证的相同合成请求去重；已完成的缓存跨重启可复用。缓存缺失或生成未成功保存时，下次重试可能再次计费。
- 音频及元数据可随 Git 提交，学习进度仍存放在 `user/`，与语音配置独立。

**本地接口**（限可信本机使用，非公共付费代理）

| 接口 | 用途 |
|------|------|
| `GET /api/tts/status` | 供应商服务端凭证是否存在、业务空间是否配置、默认选择；不返回 Key |
| `GET /api/tts/variants?text=...` | 返回 `{variants:[{id,provider,model,voice,format,sampleRate,generatedAt,legacy?}]}`，仅列出实际存在的文件 |
| `GET /api/tts/audio?text=...&id=...` | 仅播放指定缓存，不合成；缺失返回 404 |
| `POST /api/tts` | JSON `{text,selection:{provider,model,voice}}`；优先缓存，缺失才合成，返回 `audio/wav` 或 `audio/mpeg` |
| `GET /api/tts?text=...&voice=...` | 兼容旧火山引擎调用，缺缓存时可能合成 |

合成请求使用 `X-Volc-Api-Key` 或 `X-Bailian-Api-Key`，百炼可附带 `X-Bailian-Workspace-Id`；页面只发送当前供应商的凭证。代理只把该 Key 发给相应供应商，下载百炼结果文件时不携带 Key。文本上限 600 字符；跨源请求拒绝。请使用 `npm run web -- --host 127.0.0.1`，不要把付费代理直接公开到互联网。

接口与音色依据：[Qwen API](https://help.aliyun.com/zh/model-studio/qwen-tts-api)、[Qwen 音色](https://help.aliyun.com/zh/model-studio/qwen-tts-voice-list)、[CosyVoice HTTP API](https://help.aliyun.com/zh/model-studio/cosyvoice-tts-http-api)、[CosyVoice 音色](https://help.aliyun.com/zh/model-studio/cosyvoice-voice-list)。新增自动测试使用模拟响应，不消费真实配额；实际音质与账号可用性需要配置真实凭证后手动试听验证。

### Web 日语输入

- 默认使用内置罗马字输入：保持英文输入法，输入 `isshoni` 得到 `いっしょに`。切到 `ア` 后输入 `depa-to` 得到 `デパート`；切换只影响之后输入的罗马字，因此同一句可混用两种假名。
- 系统输入法模式保留原有日语输入方式。内置转换只处理假名，不提供汉字候选，也不替代其他软件里的系统日语输入法。
- 未完成的 `sh`、`ky` 等保留待输入状态，补全后才能提交；结尾的 `n` 在提交时确定为 `ん`。需要明确分隔时使用 `n'`，如 `kin'youbi`。
- 输入助手支持清音、浊音、拗音、小假名、长音和外来音查询。点击假名查看按键/别名和发音，可插入光标所在位置；键盘按钮支持输入、退格、空格和提交。
- 答错后显示按组合分段的答案标注与输入规则。可选择始终显示、答错后显示或手动查看；查看整题答案后答对会标为辅助完成，FSRS 按“难”评分。查单个假名不自动扣词汇评分。
- “假名输入练习”提供看假名打字、听音打字和易错项复练。偏好及输入练习记录写入 `user/input-learning.json`，同时在 localStorage 保留即时缓存与离线回退；首次打开新版本时会自动上传浏览器里已有的记录。不修改课程数据或终端进度结构。
- 听写仍可在同一个输入区作答；输入框内的 `p`、`s` 不会触发重听/慢速快捷键。Web 跳题使用“跳过”按钮。

### Web 情景课程

首页“今天练什么”优先继续未完成的情景练习，完成后沿学习路线推荐下一课。“情景课程”按三个阶段组织，默认展开当前推荐阶段，各阶段都可展开并自由选课，不设置硬性解锁。原有 15 门基础课与词汇复习仍在“基础巩固”，数据和流程保持不变。

#### 第一阶段：日常入门

| 课程 | 交流目标 | 阅读材料 |
|------|----------|----------|
| 01 约朋友吃饭 | 邀请、接受、婉拒、约时间地点 | 朋友的约定消息 |
| 02 在咖啡店点单 | 餐品数量、堂食外带、口味偏好 | 取餐号码与付款金额 |
| 03 问路与确认方向 | 问位置、确认转弯、询问用时、请求重复 | 图书馆开放时间与休馆日 |
| 04 买衣服与询问尺码 | 问颜色尺码、请求试穿、更换尺码、询问付款 | 价格牌与付款方式 |

#### 第二阶段：接续交流

| 课程 | 交流目标 | 阅读材料 |
|------|----------|----------|
| 05 认识新朋友，接着聊下去 | 自我介绍、互问爱好、接受邀请并追问 | 活动集合与雨天安排 |
| 06 确认车次与换乘 | 确认去向、问时间站台、核对换乘 | 练习用时刻表 |
| 07 办理入住与提出需求 | 核对预订、加早餐、寄存行李 | 本课入住须知 |
| 08 商量周末安排 | 说明空闲时间、商量集合、约定订票分工 | 订票与集合消息 |

#### 第三阶段：处理变化

| 课程 | 交流目标 | 阅读材料 |
|------|----------|----------|
| 09 临时有事，重新约时间 | 解释原因、协商改期、核对新安排 | 改期确认消息 |
| 10 想点的卖完了怎么办 | 询问替代品、保留偏好、接受或婉拒替换 | 订单修改单 |
| 11 尺码不合适，协商换货 | 说明问题、回应凭证询问、协商替代品 | 本课店铺告示 |
| 12 没听懂时，把信息问清楚 | 询问词义、核对并修正、请求写下来 | 接待处与会场便条 |

前四课维持原有 4 段发言和 2 次回应；新增八课各有 6 段发言和 3 次相关回应，完成全部回应后进入迁移练习。每课都包含 3 道听力理解题、4 组常用表达、1 次迁移表达和 2 道阅读理解题。

新课提供“温习”入口，返回使用过相关表达的旧课；例如缺货点单衔接咖啡店点单，换货衔接尺码询问，澄清信息衔接问路。第三阶段的迁移题会改变条件，有时需要拒绝刚才接受的方案，不只是替换一个名词。这些是预编排练习和口语自评，不是实时识别语音的自由对话，也不代表完整日语课程或正式能力等级。

流程以第一课为例：

1. **听懂对话**：先听完整对话，判断邀请内容、时间和地点；原文、中文与慢速播放按需使用。
2. **积累表达**：学习邀请、接受、婉拒与约定的常用表达，支持假名注音、罗马音及朗读。
3. **开口回应**：先说自己的回答，再看多个参考表达，对照表达要点自评；不要求逐字一致，也不以拼写为通关条件。
4. **换个情景**：把吃饭换成周日喝咖啡，并改变见面时间、地点，练习迁移表达。
5. **读懂消息**：阅读含汉字的自然日文，区分见面时间、预约时间和路程；可按需展开假名、罗马音及中文。

- 理解题保存第一次作答，答错会给出解释。回顾主数字显示总答对数，借助辅助答对也计入；下方分别显示无提示答对、借助辅助答对，以及本环节使用过的慢速、原文、注音、罗马音和中文释义。新作答记录每题作答前用过的辅助，关闭提示不清除已查看的记录；旧记录保留原始结果，不补猜逐题辅助详情。下一步建议区分答错重练与答对后逐渐减少辅助。口语明确标为自评，不提供自动语音识别、发音或语法评分。
- 可选录音只在点击按钮后请求麦克风，最长 60 秒，只在当前页面回听。离开回应题或情景课会释放设备并清除录音，不上传、不持久化；拒绝权限仍可直接开口后自评。
- 听力可使用已缓存录音、云端合成或浏览器的日语音色，录音需要 HTTPS 或 localhost/127.0.0.1 等安全上下文。缺少语音时可以用原文继续，但不会计为独立听懂；不需要安装日语输入法。
- 分课断点、各题结果、完成轮数、历史回顾及未完成的单项重练保存在 `user/scenarios.json`，同时写入 localStorage（`jp-learn-scenarios-v2`）作为即时缓存与接口不可用时的回退。打开页面时优先读取文件；文件不存在而浏览器已有记录时，会自动上传旧记录。自动迁移 `jp-learn-scenario-v1` 的试验课记录，保留旧键不覆盖。旧版只有最近一轮详情，因此迁移时保留该轮与累计次数，不虚构更早的历史记录。
- 四课版本的 v2 记录直接兼容：旧课程 ID、题目与编号保持不变，新增课程补上空白进度，旧答案、历史和未完成单项练习均保留；学完原四课后可从第 5 课继续。
- 可随时返回首页或刷新后继续；进度文件可随 Git 提交同步到其他设备。不同浏览器、域名或端口仍有各自的本地缓存，但打开页面后会以 `user/scenarios.json` 为准；清理浏览器数据不会删除文件。保存失败时页面会提示。仍不修改 `user/progress.json` 的 FSRS 数据。
- “再练一轮”创建新的本轮答案，保留累计次数与已完成轮次的历史快照。首页“最近一次练习”展示真实完成时间和结果，不把昨日记录算作今日成绩；“练习记录”可回看每次结果。
- 单项重练只练一个口语回应、听力段或阅读段，先尝试再看参考。完成后保存为单独记录，不覆盖完整课程，也不增加整课完成次数；后续推荐会参考重练结果。未完成的单项练习可从首页继续。
- 回顾区分理解题结果和口语自评，不把单次答对或自评当作长期掌握；未完整播放对话时，首页标为“对话文字理解”，回顾也说明未完成听力。
- “查看进度”以四维练习雷达为主，逐课回顾与基础巩固明细可展开查看。雷达支持最近 30 天（滚动时间窗口）与全部记录，只使用已完成课程和已完成单项练习的历史快照，不把进行中的练习或旧版累计次数补成历史成绩。
- 雷达显示**独立完成比例**：听力、阅读为“无提示答对题数 / 题数”，开口回应、迁移表达为“自评能独立表达项数 / 项数”；理解题总答对数同时展示，辅助答对不算答错。四轴是练习记录而非正式能力分数，不能跨轴推断语言水平。无记录显示“待积累”且不画数据点，只有一个情景时提示样本较少。“原课练习”“全部变体”“隔日复测”分开统计，变体结果不覆盖原题结果；全部变体包含提前练习和到期复测，隔日复测只使用符合间隔要求的记录。
- 同一情景的同一题，只取所选时段最近一次结果；单项重练只更新其对应题目，不覆盖原课程回顾。另列完成次数、情景覆盖数、最近时间、作答前辅助及逐题来源。未完整播放音频的文字理解不计入听力，也不覆盖此前真实的听力记录；旧记录缺失的逐题辅助不猜测补全。
- 各维度可回看来源记录并进入单项重练，优先选择答错或自评还想练习的项，其次是需要辅助的项；全都独立完成时优先复测较早的记录。变体入口进入整组变体，不假称只练某一维度。已有未完成的单项或变体练习时先继续原练习，不静默丢弃进度。雷达完全从历史记录派生，不保存额外的能力分数。
- 试验课与内容类型在 `web/scenario/content.ts`，其余入门课在 `courses.ts`，第二、三阶段分别在 `courses-conversation.ts`、`courses-adaptation.ts`；路线与课程目录在 `catalogue.ts`，单课评分在 `progress.ts`，多课存储与推荐在 `library.ts`。均独立于自动生成的 `data/lessons.json`，目前仅在 Web 端提供。
- 增加课程时使用新的稳定 ID，配置完整听、说、读内容与答案解释；`buildsOn` 只能指向路线中更早的课程。已有课程的题目含义不可在同一 ID 下随意替换，以免历史成绩失去对应依据。车次时刻、价格与店铺规则均为练习设定，不作为实际出行或消费信息。

试用时重点观察：能否不看参考回应邀请、换时间地点后还能表达、读消息时能否找到需要的信息。隔一天再试一次，比当场背出原句更能反映是否需要调整练习方式。

### 下一阶段计划

已落实本轮的隔日再测与同场景变体，后续优先根据试用结果调整间隔和题目难度，再增加材料 C、生活办事、工作沟通及更长的阅读材料。当前不提供自动出题、无限随机对话或自动口语评分。

### 隔日再测与变体

- 学完一个情景后，首页出现“隔日再测”。初次等待完整 24 小时，到期后可开始；“复测安排”列出所有已学情景的下一次时间，也允许提前练习。页面打开期间会定时及在窗口重新获得焦点时更新到期状态，不发送系统通知。
- 每课增加一套固定编排的**材料 B / v1**，共 12 套。新材料有独立的场景 ID 和题目 ID，包括 4 段新发言、2 道听力题、1 次回应、1 次条件迁移、1 条新消息和 2 道阅读题。变化包括取消饮品、先寄存行李、无法等待补货、先取号再上楼等，不只是替换人名。没有自动随机生成，也不会把重复做过的材料称为全新材料。
- 流程为“听懂新对话 → 接一句话 → 改变条件 → 读懂新消息”，不先展示表达教学。辅助仍可用；每题第一次答案、作答前辅助及口语自评沿用原有规则。未完整播放音频不计独立听力；录音仍只在当前页面本地回听。
- 间隔按 **1 → 3 → 7 → 14 天**安排：到期复测的理解题全部无提示答对，且两项表达均自评独立，才延长到下一档；14 天封顶。复测或提前变体练习有错题、辅助、未播放音频或表达仍需练习时回到 1 天。提前独立完成不会延长档位，也不算隔日保持。它是透明的练习规则，不是经校准的记忆预测，不复用词汇 FSRS 评分推算口语能力。
- 时间从上次接触材料重新计算：完成原课、单项练习或变体会更新起点；打开已学原课或回看历史记录也会留下接触时间。刚温习后不能立即算隔日复测。开始时未到期，即使拖到到期后完成仍属提前练习；开始后中途回看原材料或进行其他相关练习，也降为普通变体练习。
- 未完成的变体支持返回首页和刷新续练，与未完成的单项练习互斥，避免静默覆盖。完成后保存独立快照与材料版本、开始时间、间隔起点和练习类型，不覆盖原课答案、不增加原课完成轮数。回顾显示本次是否属于隔日复测和当前下次安排。
- 继续使用 `jp-learn-scenarios-v2`：新增 `revisit` 断点、`exposures` 接触时间记录，以及 `attempts` 中的 `revisit` 类型和版本元数据。旧 v2 缺字段时补空值，v1 迁移流程不变，已有历史不会被重新标成隔日保持；未知材料版本、错配场景和非法时间不作为有效复测导入。数据写入 `user/scenarios.json`，并保留 localStorage 作为缓存；`user/progress.json` 仍只存基础课 FSRS 数据。
- 材料在 `web/scenario/variants.ts`，间隔、完成和解析逻辑在 `revisit.ts`，首页安排和复测界面分别在 `RevisitHome.tsx`、`RevisitLesson.tsx`。改写题意必须创建新的材料版本和 ID，并保留旧版定义供历史回看。车次、运费、退换货及旅馆政策都是练习设定。

## 学习进度文件与同步

Web 版通过 Vite dev/preview 的 `/api/state/<name>` 接口把学习进度写入仓库内的 `user/`：

| 文件 | 内容 |
|------|------|
| `user/progress.json` | 15 门基础课的 FSRS 条目与已完成课程 |
| `user/scenarios.json` | 12 门情景课、变体、单项重练、复测安排与历史快照 |
| `user/input-learning.json` | 假名输入偏好与练习历史 |

- 页面打开时优先读取文件；接口不可用（例如静态部署）时回退 localStorage。每次修改同时更新 localStorage 和文件。
- 首次从旧版本升级时，如果文件还不存在，页面会把 localStorage 中已有的情景与假名记录自动上传到对应文件。
- 这些文件是普通 JSON，会出现在 `git status` 中。应用不会自动执行 `git commit`；学习后手动提交即可随仓库同步：

```bash
git add user
git commit -m "chore: update learning progress"
git push
```

- 按单用户、单写入者设计，冲突时后写覆盖。换设备前先 `git pull`；同一时间只在一个浏览器里练习，避免两个标签页互相覆盖。上一次文件写入失败时会在 localStorage 留下 pending 标记，下次打开优先保留本地修改并重试上传。
- 语音 API Key 不写入这些文件：页面输入的 Key 只存在 sessionStorage，`.env` 中的服务端 Key 不会进入仓库。

## 验证

```bash
npm run typecheck
npm test
npx playwright install chromium
npm run test:web
```

`typecheck` 同时检查终端版（`src/`）与 Web 版（`web/` + `vite.config.ts`）。

逻辑测试覆盖假名、12 课与 12 套变体完整性、路线关系、评分、阶段解锁、旧版兼容、历史快照、单项重练、复测间隔推进与重置、提前练习、温习重计时、版本校验、同步文件选择与白名单存储，以及雷达的时间过滤、逐题去重、来源隔离、辅助记录和缺失维度；浏览器测试覆盖原有练习、12 课与 12 套变体完整流程、自由选课、断点恢复、语音降级、录音生命周期、复测计时、雷达回看重练闭环、进度文件上传与无 localStorage 恢复及桌面/手机布局。浏览器测试拦截 `/api/progress` 与 `/api/state/**`，不会写入实际学习进度；录音测试使用模拟权限或浏览器合成测试音源，不访问真实麦克风。

如果已有 Chrome，也可跳过浏览器下载，直接指定系统 Chrome 运行测试：

```bash
# macOS / Linux
PLAYWRIGHT_CHANNEL=chrome npm run test:web

# Windows PowerShell
$env:PLAYWRIGHT_CHANNEL='chrome'; npm run test:web
```
